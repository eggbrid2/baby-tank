# AI 表情控制契约

日期：2026-10-16
固件：`baby_tank_head 0.8.0`
状态：控制层已实现并通过构建；等待设备手动进入下载模式后完成本版本真机烧录验证。

## 目标与非目标

目标是让后续语音或大模型模块能够表达有限的情绪意图，同时保证角色形象、动画节奏和系统安全仍由确定性固件控制。

本版本不是 AI、联网或 JSON 服务实现，也没有引入小智、云端 SDK 或模型凭据。它只建立 AI 与动画之间的本地边界。

## 为什么不让 AI 直接生成动画参数

模型直接输出坐标、颜色、眼睑高度或逐帧数据会带来以下问题：

- 同一情绪在不同回答中改变角色身份；
- 越界数值造成闪烁、遮罩错误或计算负担；
- 高频输出不断重启动画，形成机械抽搐；
- AI 指令越权覆盖触摸反馈、故障状态或安全提示；
- 模型与固件版本强耦合，后续难以调整美术而不改提示词。

因此 AI 只能提交白名单语义，固件拥有最终解释权。

## 建议的模型结构化输出

未来 AI 服务可输出：

```json
{
  "emotion": "curious",
  "intensity": 70,
  "duration_ms": 3200
}
```

网络或模型适配层负责 JSON 解析；解析完成后调用：

```c
baby_tank_face_submit_ai("curious", 70, 3200);
```

### 白名单字段

- `emotion`：必须是 24 个固件名称之一；精确匹配、小写英文、最长 32 字节；
- `intensity`：固件钳制到 `20..100`；
- `duration_ms`：固件钳制到 `1200..30000 ms`；
- AI 不提供 `priority`、坐标、颜色、速度曲线或循环次数。

支持的名称：

```text
calm happy laughing excited love curious surprised shy proud bored
annoyed complaining angry furious sad crying worried confused dizzy sick
thinking sleepy sleeping bubble
```

非法名称返回 `ESP_ERR_NOT_SUPPORTED`，不会降级猜测相近词。语义映射应在 AI 适配层显式完成，例如把“frustrated”映射成 `annoyed` 或 `complaining`，而不是在底层模糊匹配。

## 优先级和打断规则

| 层级 | 值 | 用途 | 可打断 |
| --- | ---: | --- | --- |
| Idle | 0 | 自动恢复的 `calm` | 被任何请求打断 |
| Ambient | 20 | 当前演示轮播、未来环境闲置行为 | 只能打断 Idle/Ambient |
| AI | 50 | 对话情绪和语义反应 | 打断 Ambient；不能打断 Interaction/Safety |
| Interaction | 70 | 触摸、按键、明确用户动作反馈 | 打断 AI 与 Ambient |
| Safety | 100 | 故障、急停、电量或运动安全提示 | 打断所有较低层级 |

同优先级的新请求覆盖旧请求。控制任务每帧清空请求队列并选择其中最高优先级；同级选择最后到达者。低于当前活动优先级的请求被明确丢弃并记录日志，不会在几秒后突然补播过时情绪。

AI 入口固定使用 `AI=50`，模型无法伪造安全级优先权。可信固件模块才能使用通用 `baby_tank_face_submit()`。

## 时间与强度

- 控制器以 20 FPS 独占调用屏幕渲染，其他任务不直接访问 LCD；
- 请求到期自动恢复 `calm`，不会无限保持模型情绪；
- 动画返回阶段按请求时长比例调整：约 70% 处开始收尾，约 79% 处回到母版；
- 强度只缩放母版到目标表情的形变量和漫画提示，不改变配色、基础位置或动作原则；
- 即使模型请求 0 强度或超长时间，也会被限制在可接受区间。

## 并发与资源边界

- 请求队列固定为 8 条，不进行动态增长；
- 队列满时返回 `ESP_ERR_TIMEOUT`，调用者应合并或丢弃旧情绪，不能阻塞音频链路；
- 表情任务是 LCD 的唯一所有者，避免 AI、触摸和状态机并发写屏；
- `baby_tank_face_get_snapshot()` 提供线程安全的当前状态快照，供未来日志、网页或遥测读取；
- 当前轮播通过 Ambient 请求进入同一控制层，不再直接调用渲染器。

## 文件职责

- `face_controller.h/.c`：公开请求结构、白名单 AI 入口、队列、优先级、到期与快照；
- `display_runtime.c`：稳定显示编译入口和自然微动作；
- `premium_face.inc`：母版参数、动态时长、强度缩放与最终绘制；
- `app_main.c`：当前 Ambient 演示生产者，未来接入正式行为状态机后应移除轮播。

## 后续 AI 接入顺序

1. 先实现语音状态机的确定性事件：监听、思考、说话、失败；
2. 将这些系统状态映射到 `Interaction` 或固定系统表情，不交给模型决定；
3. 再让模型输出可选的对话情绪，使用 AI 优先级；
4. 对模型输出做 JSON Schema 校验、限频和去重；
5. 最后再接网络服务、凭据保护、TLS、超时与离线降级。

“正在监听”“网络失败”“电量低”和“急停”不应被当作模型情绪。这些是系统事实，必须由本地状态机以更高优先级驱动。

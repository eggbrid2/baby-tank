# “喵喵同学”宝宝人格与触摸唤醒记录

日期：2026-10-16
目标固件：`baby_tank_head 0.10.0`
状态：人格约束、四轮易失短期上下文、顶部触摸唤醒与 WakeNet 模型选择已通过本机构建；音频闭环尚未接通；未烧录。

## 产品判断

Baby Tank 的定位是“正在认识世界的机器人宝宝”，不是猫，也不应模仿真实婴儿的错误发音。产品唤醒词“喵喵同学”是它听得懂的名字，不改变角色物种。

目标气质：

- 好奇、真诚、稍微淘气，但不装傻；
- 先回应孩子的情绪或发现，再给出简短回答；
- 通常说一到三句自然口语，偶尔使用轻微拟声词；
- 合适时最多追问一个问题，不机械地每轮追问；
- 不反复自称、不持续卖萌、不用错误发音假装低龄；
- 不要求孩子保密，不宣称比家人重要，不用内疚或孤独感制造依赖；
- 危险、健康和隐私问题引导孩子找可信任的大人。

这套提示词只能约束表达风格，不能代替儿童内容分类、监护人控制、费用限制或服务端审计。

## 为什么增加短期上下文

旧实现每轮只发送当前识别文本，模型不知道上一轮说过什么，容易像一次性客服。现在设备在 RAM 中保存最近四轮用户与助手消息：

- 仅用于当前运行会话，不写 Flash/NVS；
- 重启、重新初始化或显式调用 `baby_tank_cloud_reset_conversation()` 后清空；
- 固定容量，避免对话无限增长挤占内存或扩大请求费用；
- 这是对话连贯性，不是儿童档案或长期记忆。

长期偏好和家庭信息如果以后需要，必须先设计监护人授权、查看、修改、删除和保存期限，不能默认悄悄收集。

## 触摸唤醒

首版只把顶部触摸区作为对话入口。硬件证据来自上游 SparkBot BSP：顶部对应触摸通道 1，原灵敏度系数为 3.5%。当前实现使用 ESP-IDF 6.1 新触摸驱动：

1. 启动时连续扫描三次建立本机基准；
2. 使用基准值的 3.5% 作为初始相对阈值；
3. 触摸中断只唤醒 FreeRTOS 任务；
4. 任务做 450 ms 去抖，再请求 `listening` 状态；
5. 触摸发生在 AI 说话期间时记录为 barge-in 请求，但真正停止扬声器仍需未来音频编排器完成。

侧面两个触摸区暂不绑定功能，防止在实机校准前误触发运动或对话。

## 待机表现

启动主循环不再每六秒轮播全部表情。那是开发阶段的展示逻辑，会让角色像表情样机，也可能与触摸和 AI 对话状态争夺控制权。正常运行现在保持带眨眼和微动的平静宝宝脸；其他表情只由对话状态、可信交互事件或经过白名单校验的 AI 情绪触发。

## AI 语音闭环还缺什么

```text
WakeNet“喵喵同学” 或 顶部触摸
                 -> listening 表情
                 -> ES8311/I2S 录音 + VAD
                 -> 一句话 PCM 上传 ASR
                 -> 带四轮上下文的 LLM JSON
                 -> 情绪白名单 + TTS
                 -> 解码 PCM、嘴部包络和扬声器播放
                 -> idle
```

当前已有云端 ASR/LLM/TTS 客户端和表情桥接，但仍缺 ES8311 驱动、录音缓冲、VAD 编排、MP3 解码与播放，以及说话时触摸打断音频的控制接口。因此本版本不能声称已经能完成语音对话。

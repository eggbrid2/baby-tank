# Baby Tank PCM 对话运行时记录

日期：2026-10-16
源码版本：`baby_tank_head 0.11.0`
设备烧录：未执行；实物仍运行已验证的 `0.7.0`

## 本次目标

把既有漫画宠物表情、顶部触摸和“喵喵同学”本地唤醒词接到真实的
ASR → LLM → TTS 链路，并按用户决定把下行音频固定为原始 PCM，避免在
ESP32-S3 上加入 MP3/Ogg/Opus 解码器。

## 已实现的固件链路

1. ES8311 通过 I2C1 初始化；I2S1 使用 16 kHz、16-bit、单声道、全双工 PCM。
2. AFE 在本地持续接收麦克风 PCM。WakeNet 只在待机态监听固定模型
   `wn9_miaomiaotongxue_tts`，不依赖云 ASR。
3. WakeNet 或顶部触摸进入聆听态。VAD 最多等待 5 秒起声，最多录制 12 秒，
   检测到 700 ms 尾部静音后结束。
4. 一次录音以 PCM 上传至云端 Paraformer ASR；识别文本进入最多四轮、仅存
   RAM 的对话上下文。
5. 模型回答只可通过表情白名单和强度边界影响面部动画，不能直接控制像素、
   优先级或任意时长。
6. TTS 返回的分块 PCM 直接写入 I2S；写入前同一批采样用于计算嘴型能量。
7. 处理或播放期间再次触摸会请求取消当前 HTTP 操作，并在收尾后立即重新
   进入聆听。第一版为半双工，播放时暂停麦克风采集，避免扬声器内容被重新
   识别成用户输入。

## 固定音频协议

- 编码：headerless PCM S16LE
- 采样率：16,000 Hz
- 声道：1
- 数据率：32,000 B/s（256 kbit/s，不含 HTTP/TLS 开销）

PCM 省去了解码器与帧封装，但带宽明显高于 Opus，也没有天然的丢包恢复、
抖动缓冲或回声消除能力。固件会拒绝格式或采样率不同的 TTS 响应，避免把
压缩数据误当 PCM 播放。

## 云端故障与修复

管理页面在编辑既有火山 TTS 配置时，会先把 Resource ID 填成默认
`seed-tts-2.0`。由于凭据原文不会回显，提交音频格式变更时这个默认值覆盖了
克隆音色所需的 `seed-icl-2.0`，上游报错：Resource ID 与 Speaker 不匹配。

修复后，既有供应商配置不再自动填写凭据默认值；留空会保留数据库中已加密
的原值。服务器配置已恢复为 `seed-icl-2.0`。系统音色和克隆音色使用的资源
并不相同，不能只依据模型名推断 Resource ID。

## 已完成验证

- `npm run check`：通过。
- `npm test`：1 个集成测试通过；覆盖管理员、供应商凭据合并、设备接口与
  OTA 基线。
- ESP-IDF 6.1 `idf.py -C firmware/head build`：通过。
- 固件镜像：`0x1af2a0` 字节；最小应用分区 `0x600000`；剩余 72%。
- 火山 TTS 真实请求：返回 `pcm/16000`，测试音频 172,188 字节且长度为偶数。
- 阿里 Paraformer 真实回环：上述 PCM 准确识别为“你好，我是喵喵同学。”。
- 当前 DeepSeek `deepseek-v4-flash` 真实请求：返回有效文本“收到”。
- 公网 `/healthz`：部署后返回 `status=ok`。
- LLM 的 12 KiB 响应缓冲改为优先分配在 PSRAM、失败时回退普通堆，避免
  超过 10 KiB 对话任务栈；修改后重新构建通过。
- 未执行任何硬件烧录。

## 凭据与配网边界

固件不包含 Wi-Fi、设备令牌或第三方供应商密钥。运行时只从 NVS 命名空间
`baby_tank` 读取 `wifi_ssid`、`wifi_pass` 和 `device_token`。辅助脚本
`tools/generate-head-credentials.sh` 使用环境变量生成 16 KiB NVS 镜像，不把
值放进命令行参数，也不会烧录。输出文件权限为 0600，并位于忽略目录。

当前开发版没有启用 NVS Encryption，所以这个镜像和设备 Flash 中的凭据仍
应按明文秘密管理。此前在聊天中出现过的设备令牌不应继续用于真实设备，必须
先在后台轮换。

## 尚未验证与风险

- 编译成功不能证明 ES8311 引脚、时钟、麦克风偏置、扬声器增益或声道格式在
  实物上正确。
- WakeNet 的模型已打包，但尚无真实环境误唤醒率、漏唤醒率和距离数据。
- PCM 下行没有独立 jitter buffer；弱 Wi-Fi 下可能出现 I2S 欠载或停顿。
- 关闭 AEC 且采用半双工。若未来要求自然抢话，需要同时解决 AEC、参考信号、
  延迟对齐和全双工状态机，不能只在播放时重新打开麦克风。
- HTTP 取消为协作式取消；DNS、建连或上游长期无数据时，触摸不一定瞬时打断。
- SoftAP/二维码配网尚未实现；当前 NVS 镜像只是开发阶段接入手段，不是最终
  家庭用户流程。
- 儿童产品仍缺监护人额度、静音时段、内容策略审计、隐私说明和数据删除入口。

## 下一次实物验收顺序

1. 轮换设备令牌，生成新的本地 NVS 凭据镜像并验证原始 Flash 备份哈希。
2. 只烧录头部固件与凭据分区，先观察启动日志、堆内存和 PSRAM。
3. 单测麦克风 PCM 的直流偏置、峰值、噪声底与近讲音量。
4. 单测扬声器 16 kHz PCM 的速度、声道、削波和电流峰值。
5. 统计至少 100 次安静/电视/儿童说话条件下的 WakeNet 结果。
6. 验证触摸唤醒、5 秒无声超时、12 秒上限、断网恢复和播放中打断。
7. 连续运行语音闭环后，再逐步加入摄像头与底盘负载。

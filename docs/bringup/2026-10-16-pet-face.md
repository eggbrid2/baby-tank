# 自研宠物脸实现记录

> 状态更新：本文记录的 `0.3.0` 猫脸因实体观感过于复杂、略显诡异，已于同日被 `0.4.0` 极简眼睛与嘴巴版本替换。当前状态见 `2026-10-16-generated-minimal-face.md`。

日期：2026-10-16
固件：`baby_tank_head 0.3.0`
目标：将屏幕上的 `HELLO WORLD` 替换为可继续扩展的自研宠物脸。

## 前提检查与设计选择

“GitHub 上有宠物脸项目”不等于“存在可直接用于本机的固件”。本机是 ESP32-S3、240×240 ST7789、ESP-IDF 原生 `esp_lcd`；检索到的多数项目是 Arduino、Adafruit GFX/TFT_eSPI 或 128×64 单色 OLED，显示栈、分辨率和硬件引脚都不匹配。

用户没有指定动物种类，本版采用“橙色猫脸”作为可逆的产品假设。猫耳、胡须和鼻口能在小屏幕上明确表达“宠物”，后续可在不改底层 LCD 驱动的前提下更换造型。

## GitHub 方案调研

| 项目 | 许可证 | 可借鉴点 | 不直接合入的原因 |
| --- | --- | --- | --- |
| [FluxGarage/RoboEyes](https://github.com/FluxGarage/RoboEyes) | GPL-3.0 | 自动眨眼、视线和情绪参数 | Arduino + Adafruit GFX + OLED；GPL 还会影响本固件分发边界 |
| [tanmaywankar/Grobot_Animations](https://github.com/tanmaywankar/Grobot_Animations) | MIT | 表情状态机、弹簧式平滑运动、彩屏方向 | Arduino + TFT_eSPI，不匹配现有 `esp_lcd` 驱动 |
| [RobotStudyCompanion/CYD](https://github.com/RobotStudyCompanion/CYD) | Apache-2.0 | 彩屏脸与菜单分层、串口控制表情 | 面向 ESP32-2432S028R，依赖 Grobot/TFT_eSPI/GUIslice |
| [ZnFr60/ESP32C3-Desk-pet](https://github.com/ZnFr60/ESP32C3-Desk-pet) | 未声明 | ESP-IDF 下的情绪/动画组织方式 | OLED 硬件不同；未声明许可证意味着不能假定可复制其源码 |
| [ThomasHelman123/Animated-Robot-Face-on-ESP32-CYD-with-Floating-Heart-Eye-Animations](https://github.com/ThomasHelman123/Animated-Robot-Face-on-ESP32-CYD-with-Floating-Heart-Eye-Animations) | 未声明 | 局部合成、减少动画闪烁 | PlatformIO + LovyanGFX，且未声明许可证 |

结论：只采用公开项目展现出的通用设计思想，不复制其代码或素材。本版保留现有原生 ESP-IDF 显示链路，并实现自己的 RGB565 几何渲染器。这避免了许可证不确定性、驱动冲突和额外依赖成本。

## 本版实现

- 深色背景、橙色猫头、粉色耳朵和鼻子、青绿色眼睛、腮红、额头纹和胡须。
- 图像由矩形、圆、椭圆、三角形和 Bresenham 线段直接绘制，没有外部位图或字体。
- ST7789 设置为 RGB565 little-endian，使源代码中的 RGB 值可直接写入 `uint16_t` 帧缓冲。
- 仍使用 240×240×2 字节内部 DMA 帧缓冲，共 115200 字节。
- 当前是静态表情。眨眼和视线移动应在下一步加入独立的表情状态层，而不是把时序逻辑塞进 LCD 初始化函数。

## 已知边界与后续风险

- 串口日志只能证明 LCD 初始化和帧传输 API 成功，不能替代人眼对颜色、方向和构图的确认。
- 当前整帧常驻内部 DMA RAM；静态画面成本可接受，但做高帧率动画前应改为局部脏矩形或条带缓冲，避免 RAM 和 SPI 带宽浪费。
- GPIO46 仍可能与音频功放使能复用；启用音频前必须验证并统一管理该引脚。
- 参考项目最吸引人的通常是大量表情数量，但“表情多”不等于体验好。优先级应是无闪烁的眨眼、自然注视和明确的状态映射，再扩展表情数量。

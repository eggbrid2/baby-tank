# 2026-10-17 AI 表情时间轴与看图动作组

## 事实与实现边界

- 头部 `0.13.8`：TTS 回答按最多三句云端合成，响应头携带 PCM 采样点对应的情绪切换；说完后最后一种表情保留 3 秒。嘴型仍跟随设备播放的 PCM 包络。句子切分不合法时云端退回单一情绪。
- 明确说“去看看前面有什么”等窄语法，云端才授权一次探索会话。头部在回答后先核对底盘 STOP，再拍一张 240×240 JPEG；云端把这张照片交给 Qwen VL 分析，返回至多一条方向、时长、表情及底盘预设灯效。头部执行完一步并上报后重新拍照、重新规划，而非一开始排死整组动作。
- 云端和头部均限制每组最多 3 步、运动累计最多 15 秒、单步 2–9 秒。头部每约 80 ms 刷新 UART 运动命令，底盘回显不符即停止；BLE 控制或 STOP 抢占动作组。动作组期间再次触摸头顶也会发 STOP。任一拍照、视觉 API、格式校验、灯光回显、运动回显、结果上报失败均不继续下一步。
- `ai_exploration_events` 记录 `authorized / observed / planned / completed / stopped / blocked / failed`，只存照片字节数，不存照片。照片在头部和云端仅作为当次请求的临时内存数据，云端会转发给阿里云视觉模型；需把这一第三方处理及推理费用告知监护人。
- 当前底盘固件只支持灯效模式 `2=白灯`、`6=彩虹`、`8=休眠`。休眠会淡出，不保证立刻熄灭；任意 RGB 颜色尚不支持，不能把灯效选择宣称为任意颜色控制。

- `npm test && npm run check` 通过；测试覆盖明确探索口令、否定/假设拒绝、视觉模型越界动作拒绝、云端授权、照片格式、重复请求、逐步执行日志和 STOP。
- ESP-IDF 构建通过，镜像约 2.25 MB，应用分区仍有约 64% 空间；仅向头部 `ota_0` 的 `0x100000` 写入，esptool 写入哈希验证通过。原 0.13.5 备份见 `docs/bringup/2026-10-17-ai-drive-and-ble-control.md`。
- 云端重新构建并通过 `/healthz`。现有阿里云凭据调用 `qwen3-vl-flash` 得到 `model_not_found`，因此改为实测可用的 `qwen3-vl-plus`。用阿里云公开“人与狗”样例图测试新视觉提示，模型返回 `stop`，本地严格解析器接受。
- 头部启动日志显示 `0.13.8`、已连接“泡面”Wi-Fi、云端健康检查通过、GC2145 摄像头初始化成功。**尚未把以上静态/云端测试误称为视觉动作组的实机成功**；需在履带架空时检查一次完整的照片上传、视觉推断、灯效及停车回显。
- 第一轮触摸语音实测录到了 12 秒上限，云端把模型动作拒绝为非明确授权，没有发送电机命令。该轮头部记录了第二句情绪采样点切换及回答后 3 秒保留；PCM 播放最小缓存余量仍为 `-750 ms`，不能宣称已消除卡顿。随后云端增加“探索前回应不超过 18 字”的指令，缩短从授权到拍照的等待；还需再次实测。

## 未解决的风险

- 这是单目照片，不是测距或避障传感器；模型即使返回 `forward` 也不能证明前方空旷。孩子近旁落地自主行走必须增加物理防撞/悬崖检测、底盘独立失联停车实测及家长可见的物理急停。当前仅作架空履带联调。
- 底盘 UART 原固件没有任意 RGB 色值命令；若需红、蓝等指定颜色，须设计新命令并单独刷底盘固件。灯效 UART 精确回显表示命令收到，不等于 LED 实际亮度测量。
- 图像之前出现过花屏；本轮仅检查 JPEG 格式与模型结果，不能凭此断言摄像头画质彻底修复。花屏或看不清时模型应停止，但视觉判断不能作为唯一安全措施。
- 设备音频播放曾出现缓存余量为负的日志；本轮句子级 TTS 增加了云端合成次数，首音延迟与设备端是否卡顿仍须实机复核。

视觉接口格式参考阿里云 [Qwen-VL OpenAI 兼容接口](https://help.aliyun.com/en/model-studio/qwen-vl-compatible-with-openai)。

# 2026-10-17 头部—底盘有线 UART 联调记录

## 目的

确认头部 ESP32-S3 能否通过磁吸/连接线向底盘 ESP32-C2 发送安全的停车与低速履带测试命令。

本记录严格区分：

- UART 通信成功；
- 底盘固件解析命令；
- 电机实际动作及方向正确。

前两项不能自动证明第三项。

## 实物与端口

- 头部：ESP32-S3，USB Serial/JTAG `/dev/cu.usbmodem311301`
  - MAC：`44:bd:8d:69:49:68`
  - 16 MiB Flash、8 MiB Octal PSRAM
- 底盘：`/dev/cu.usbserial-31110` 上的 ESP32-C2 / ESP8684H rev 2.0
  - USB 转串口：CH340，VID/PID `1a86:7523`
  - MAC：`b8:7b:4d:b4:07:10`
- `esptool chip-id` 已真实连接到底盘并识别 ESP32-C2；该命令会复位底盘，但不会擦写 Flash。

底盘完整 2 MiB Flash 已在任何改写之前备份到：

`artifacts/device-backups/20261017-chassis-esp32c2-b87b4db40710/flash-full-2MiB.bin`

SHA-256：`71059ec850b936d683215bb948eb3122c131abeaa7de952416b0270ab8fba22a`

备份中的应用描述与字符串给出以下证据：

- 项目名为 `tracked_chassis`；
- 使用 ESP-IDF 5.5.1，应用编译日期字符串为 2026-04-21；
- 包含 `tracked_chassis.c`、`motion_control.c`、`x%f y%f`、`Parsed x`、GPIO4～7 LEDC 调用和 `uart_echo_task`；
- 分区为 24 KiB NVS、4 KiB PHY、1 MiB factory 应用。

因此当前底盘镜像可确认属于上游 `c2_tracked_chassis` 同一项目/实现路径；但尚未用对应 ELF 做逐段符号或二进制同一性比较，不能断言它恰好来自仓库当前提交的无修改构建。

## UART 参数与协议

- 头部 UART1：TX GPIO38、RX GPIO48
- 波特率：115200，8N1
- 文本命令：`x%.3f y%.3f\n`
- `x` 表示转向分量，`y` 表示前后分量
- 头部速度硬限制：±600‰
- 头部命令失联停车：300 ms
- 第一轮测试：160‰（16%）、约 240 ms，电机未可靠启动
- 最终测试：600‰（60%）、700 ms，并每 80 ms 刷新命令

为避免错误前提，`baby_tank_chassis_bridge_ready()` 只代表头部 UART 驱动初始化完成，不代表物理链路已连接。固件 0.13.1 起增加完整 UART 回显匹配；移动命令只有在 STOP 获得底盘精确回显后才会放行。

## 本次源码修改

- 新增受限 USB 调试命令：
  - `motor stop`
  - `motor left`
  - `motor right`
  - `motor forward`
  - `motor backward`
  - `motor turn-left`
  - `motor turn-right`
- 不支持任意速度或任意时长输入。
- 每次履带测试前后均发送 STOP。
- 将回显等待从单次 15 ms 调整为最长 60 ms，并要求返回字节数和内容都与命令完全一致。
- 未确认回显时拒绝移动测试。
- 0.13.5 修正长脉冲测试：每 80 ms 刷新一次运动命令，避免 300 ms 头部 deadman 把标称 700 ms 的测试提前截断。

该调试控制台用于当前 USB 联调，不应未经构建开关隔离就作为量产接口保留。

## 已执行命令与结果

1. `motor stop`
   - 头部日志：`chassis link verified by exact UART echo`
   - 头部日志：`motor stop acknowledged by chassis`
   - 结论：ESP32-S3 到 ESP32-C2 的 UART 双向通信与当前文本回显行为已实测成立。
2. 第一轮单履带测试
   - 左、右履带分别以 160‰ 短脉冲测试，现场确认均未转动。
   - 这证明 16% 不是当前机构的可靠起步档，不证明精确起步阈值就是 60%。
3. 600‰ 单履带测试
   - 左、右履带分别测试，现场确认均能转动。
4. `motor forward`
   - 左右履带均为 +600‰；现场确认整车向车头前进。
   - 0.13.5 下以 80 ms 周期持续刷新满 700 ms，前进正常，结束 STOP 获得回显确认。
5. `motor backward`
   - 左右履带均为 -600‰；现场确认整车向车尾后退。
6. `motor turn-left`
   - 左履带 -600‰、右履带 +600‰；现场确认原地左转。
7. `motor turn-right`
   - 左履带 +600‰、右履带 -600‰；现场确认原地右转。

结论：头部到底盘的通信、底盘命令解析、左右通道、正反极性以及前进/后退/原地左右转的基本映射均已通过现场验证。

## 尚未由日志证明

- 负载落地时是否存在堵转、供电压降、复位或电机干扰；
- 16%～60% 之间的可靠起步阈值、左右电机差异和低速保持能力；
- 长时间连续运动时的温升、电池压降、跑偏和重启情况；
- 拔掉头部连接或停止刷新命令后，底盘约 500 ms 独立失联停车是否实物成立；
- Android 摇杆松手、App 后台、BLE 断开和头部重启时是否都能停车；
- 速度斜坡、反向切换保护和儿童使用的最终最高速度。

基础动作已经成立，但在独立失联停车和手机端断连停车完成实测前，Android 连续摇杆仍不应默认启用。60% 是本次已验证可启动的测试档，不是已经优化好的日常速度。

# Baby Tank 安全 SVG 绘画链路

日期：2026-10-19
云端：已部署
固件：`baby_tank_head 0.13.34`，已烧录头部实机

## 问题判断

旧协议最多传输 24 个 `line/circle/ring/rect` 图元，且没有曲线路径、描边宽度、圆角、层次或抗锯齿。模型输出再复杂也会被压缩成基础图元堆砌，因此“只调整提示词”不能解决画面廉价的问题。

SVG 本身只保证几何和缩放清晰，不保证构图好看。第一版让 DeepSeek 直接生成安全 SVG，虽然安全校验和渲染均已通过，但真实结果中的恐龙仍出现了抽象团块、单眼和部件关系错乱。这证明继续调提示词不能提供稳定的审美保证。

最终方案改为“模型做画面导演，设计资产负责造型”：

- 引入 `@iconify-json/fluent-emoji-flat@1.2.6`，本地包含 3,174 个风格一致的设计师 SVG；
- 模型只输出标准 Unicode emoji、中心坐标、尺寸、旋转和水平翻转；
- 云端只允许本地图库中存在的图标，模型无法注入 SVG 标记、脚本或外链；
- 固定 Baby Tank 深色背景，主体大尺寸居中，最多两个与用户描述直接相关的配角；
- 云端抗锯齿栅格化和设备端 JPEG 解码。

## 数据链路

1. ASR 确认用户有明确“画……”意图。
2. 对话模型只生成简短语音回复，不直接夹带图元。
3. 独立绘图请求只返回 1–3 个 emoji 及其排版 JSON，例如小猫+毛线球。
4. 云端把 Unicode 序列映射到本地 Fluent Emoji SVG；非 emoji、不存在的资产、越界坐标和超限尺寸全部拒绝。
5. 每个 SVG 在独立透明图层中渲染，再按经校验的布局合成，避免 ID/滤镜冲突。
6. Sharp 将合成画面以抗锯齿方式栅格化为 240×240、JPEG 94、4:4:4。
7. 设备下载最大 96 KiB 的 JPEG，在 PSRAM 解码为 115,200 字节 RGB565。
8. face controller 接管图像所有权并显示 4–8 秒，到期释放 PSRAM。

## 质量约束

- 单主体尺寸 176–196 px；有配角时主体 130–164 px，配角 42–82 px。
- 每个图层必须完整留在 8..232 的安全区内，旋转限制为 ±35°。
- 最多 3 个图层；配角只在用户明确描述场景时使用，不再自动添加彩点等无意义装饰。
- 图标轮廓、解剖关系、填色和内部细节均来自固定设计资产，因此画面形象不受文本模型绘图水平影响。
- 生成或校验失败时不显示坏图，语音回复会提示本次未画出。

## 仍需人工验收

- 用真实语音分别要求画小猫、汽车、恐龙、花和家庭场景，检查 ASR→排版→下载的完整端到端链路。
- 检查实体 ST7789 的 RGB565 色序、黑位、亮度和细线可读性。
- 连续生成至少 20 张图，确认 JPEG 下载/解码失败不会泄漏 PSRAM。
- 当前绘画是静态成图；若要动画，应基于已分离的图层做轻微入场、视差和呼吸效果，不能简单抖动整张位图。

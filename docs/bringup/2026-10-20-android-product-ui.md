# Android 产品界面与导航重构

日期：2026-10-20

## 问题判断

这次问题不是单个按钮或配色问题，而是页面骨架存在三个产品级缺陷：

1. 二级页标题和返回按钮被作为 `LazyColumn` 的第一项，因此会随内容一起滚走。
2. App 只保存一个当前页面枚举，没有处理 Android 系统返回键，也没有表达“连接页属于设置、小游戏属于交互”这类父子关系；系统返回会直接结束 Activity。
3. 首页同时承担品牌展示、状态、遥控、交互和设置入口，但旧版所有入口使用近似卡片权重，主任务不明确。

## 信息架构

- 首页：宝宝状态、遥控探险、和我说话、一起玩；设置收进右上角。
- 一起玩：玩游戏、戳一戳、喂东西。
- 设置：连接设备、音量、宝宝性格、功能检测。
- 功能检测继续作为家长/开发入口，不回到首页抢占儿童产品入口。

## 返回规则

| 当前页面 | 系统返回或左上角返回 |
| --- | --- |
| 交互内的具体玩法 | 一起玩 |
| 一起玩、设置、遥控 | 首页 |
| 连接设备、宝宝性格、功能检测 | 设置 |
| 备用网页配网 | 连接设备 |
| 首页 | 交给 Android，正常退出应用 |

遥控页离开前仍强制发送停止并退出遥控模式，不能为了导航一致性牺牲运动安全。

## 布局与视觉规则

- 二级页统一使用固定顶部栏，只有内容区滚动；返回按钮始终可见。
- 首页以深色宝宝状态卡作为角色中心，青色“遥控探险”为唯一主操作。
- 对话和互动使用等高双卡，设置不再占据一整行主内容。
- 主卡圆角 28–32 dp，普通卡 23–26 dp，横向页边距统一为 20 dp。
- 食物和游戏卡内图片改为按剩余空间自适应 `Fit`，不再依赖固定 92 dp 尺寸挤压三列布局。

## 验证边界

- Android `0.2.0`（versionCode 8）的 `assembleDebug`、`lintDebug` 和 3 个导航单元测试均通过；APK SHA-256 为 `3a39732d099a0511f29e56a6de110f39199056d25aafddc9331a64132bf17b59`。
- APK 已通过 USB 覆盖安装，`dumpsys package` 确认手机端版本为 0.2.0。
- Lint 仍报告依赖可升级、备用配网页面启用 JavaScript、局域网 HTTP 明文白名单和少量 Kotlin 优化建议；它们不是本轮 UI 重构引入的编译错误，但安全项需要在配网链路收敛时单独处理。
- 系统返回层级由 `BackHandler` 明确处理，但最终手感、不同屏幕尺寸和横竖屏切换仍需要真机解锁后的人工回归。
- 遥控页保持现有横屏布局，本轮没有重写控制协议和视频链路。
